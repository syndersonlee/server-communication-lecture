Short Polling

클라이언트가 일정 주기마다 "새 거 있어?"라고 묻는 가장 단순한 실시간 흉내내기.

아래에서 폴링을 시작한 뒤, 오른쪽 이벤트 발행 버튼을 눌러보세요. 이벤트가 없을 때도 계속 요청이 나가는 것(=낭비)을 로그에서 확인할 수 있습니다.

인터랙티브 데모

① 클라이언트 (폴러)

중지됨

총 요청 수: 0 · 빈 응답: 0 · 받은 이벤트: 0

② 이벤트 발행 (다른 사용자/시스템 역할)

이 버튼을 누른 "직후"가 아니라, 다음 폴링 주기에 데이터가 도착합니다 → 최대 주기만큼 지연.

요청 / 응답 로그

서버 코드 (Spring)

@GetMapping("/events")
public List<Event> shortPoll(@RequestParam(defaultValue = "0") long sinceId) {
    // sinceId 이후 발생한 이벤트만 반환 (없으면 빈 배열)
    return recent.stream().filter(e -> e.id() > sinceId).toList();
}

핵심 정리

단점이 그대로 보입니다. 데이터가 없어도 주기마다 요청이 나가 대부분 "빈 응답" → 트래픽/서버 낭비. 또 발행과 수신 사이에 최대 한 주기만큼 지연이 생깁니다. → 다음 실습 Long Polling이 이를 개선합니다.
