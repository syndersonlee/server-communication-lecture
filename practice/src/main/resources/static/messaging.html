비동기 메시징 (Kafka / RabbitMQ / MQTT)

"메시지를 던져놓고 내 할 일 하기." 동기 호출의 강결합·장애 전파를 끊고 시스템을 느슨하게 연결합니다.

메시지 브로커는 별도 인프라(Kafka/RabbitMQ 서버)가 필요해 이 실습 사이트에는 직접 포함하지 않았습니다. 아래 docker 명령으로 브로커를 띄우고 Spring 코드를 붙이면 바로 실습할 수 있습니다.

왜 비동기인가

[동기] 주문 ─▶ 결제 ─▶ 재고 ─▶ 알림 ─▶ 정산
       하나라도 느리거나 죽으면 전체 실패 (강결합)

[비동기] 주문 ─▶ [브로커] ─▶ 결제 / 재고 / 알림 / 정산 (각자 처리)
       주문은 메시지만 던지고 즉시 응답. 알림이 잠깐 죽어도 메시지는 큐에 보존.

RabbitMQ vs Kafka

RabbitMQKafka
모델메시지 브로커(큐)이벤트 로그/스트림
소비 후삭제보존(재처리 가능)
처리량중간매우 높음
강점복잡한 라우팅, 작업 큐대용량 이벤트, EDA 중추

로컬 브로커 띄우기 (docker)

# RabbitMQ (관리 UI: http://localhost:15672 , guest/guest)
docker run -d --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:3-management

# Kafka (KRaft 모드, 단일 노드)
docker run -d --name kafka -p 9092:9092 apache/kafka:latest

Kafka — Spring 코드

// 발행
kafkaTemplate.send("orders", String.valueOf(event.orderId()), event);

// 소비
@KafkaListener(topics = "orders", groupId = "inventory-service")
public void consume(OrderCreatedEvent event) {
    inventoryService.decrease(event.getProductId(), event.getQty());
}

RabbitMQ — Spring 코드

// 발행
rabbitTemplate.convertAndSend("order.exchange", "order.created", event);

// 소비
@RabbitListener(queues = "order.created.queue")
public void handle(OrderCreatedEvent event) { paymentService.process(event); }

MQTT

초경량 pub/sub 프로토콜. IoT·모바일 등 저전력·저대역폭 환경에 최적. QoS 0/1/2로 신뢰성 수준 선택.

비동기의 대가: 메시지 중복(→ 멱등 컨슈머), 순서 보장(파티션 키), 실패 처리(DLQ), DB-발행 정합성(Transactional Outbox). 자세한 내용은 강의 문서 09장.
