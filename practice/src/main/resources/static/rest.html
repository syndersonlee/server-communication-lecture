HTTP / REST

가장 기본이 되는 요청-응답 모델. 메서드, 상태코드, 멱등성을 직접 호출하며 확인합니다.

핵심 개념 · HTTP는 무상태(stateless)이며 요청이 있어야만 응답합니다. 그래서 서버가 먼저 데이터를 보내는 "실시간"은 기본적으로 불가능 → 이후 실습(Polling/SSE/WebSocket)의 출발점.

요청 / 응답 로그

서버 코드 (Spring)

@RestController
@RequestMapping("/api/rest")
public class RestDemoController {

    @PostMapping("/reservations")
    public ResponseEntity<Reservation> create(@Valid @RequestBody CreateRequest req) {
        Reservation created = save(req);
        return ResponseEntity
                .created(URI.create("/api/rest/reservations/" + created.id())) // 201 + Location
                .body(created);
    }

    @DeleteMapping("/reservations/{id}")
    public ResponseEntity<Void> delete(@PathVariable Long id) {
        store.remove(id);
        return ResponseEntity.noContent().build(); // 204 (멱등: 여러 번 호출해도 결과 동일)
    }
}

핵심 정리

메서드용도멱등성여기서 확인

POST생성X201 + Location
DELETE삭제O204
멱등성은 재시도 설계의 핵심입니다. POST를 무지성 재시도하면 중복 결제가 날 수 있어 멱등키 패턴을 씁니다.
