실습 3 · SYNC

Long Polling

요청을 보내면 서버가 새 이벤트가 생길 때까지 응답을 보류(hold). 이벤트가 생기면 즉시 응답 → 다시 요청.

Short Polling과 비교해보세요. 여기서는 이벤트를 발행한 "즉시" 응답이 도착합니다(지연 거의 없음). 그리고 평소엔 요청이 "대기" 상태로 떠 있어 빈 응답 낭비가 적습니다.

인터랙티브 데모

① 클라이언트 (롱 폴러)

중지됨

현재 상태: -
받은 이벤트: 0 · 타임아웃(빈 응답): 0

② 이벤트 발행

발행 즉시 대기 중인 요청으로 응답이 날아갑니다.

요청 / 응답 로그

서버 코드 (Spring · DeferredResult)

private final List<DeferredResult<List<Event>>> waiting = new CopyOnWriteArrayList<>();

@GetMapping("/long-poll")
public DeferredResult<List<Event>> longPoll() {
    // 30초 후 타임아웃되면 빈 배열 반환 → 클라가 재요청
    DeferredResult<List<Event>> deferred = new DeferredResult<>(30_000L, List.of());
    waiting.add(deferred);
    deferred.onCompletion(() -> waiting.remove(deferred));
    return deferred; // ★ 톰캣 워커 스레드는 즉시 반납됨 (스레드 점유 X)
}

@PostMapping("/publish")
public Event publish(@RequestParam String message) {
    Event event = ...;
    waiting.forEach(d -> d.setResult(List.of(event))); // 대기 요청들에 즉시 응답
    return event;
}

핵심 정리

DeferredResult의 핵심: 응답을 보류해도 서블릿 스레드를 점유하지 않습니다(Servlet 3.0 비동기). 덕분에 많은 대기 연결을 적은 스레드로 감당. 다만 매번 새 HTTP 요청을 맺는 오버헤드는 남아 → 다음은 SSE.
