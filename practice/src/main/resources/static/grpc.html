실습 6 · CONCEPT

gRPC

HTTP/2 + Protocol Buffers 기반 고성능 RPC. 주로 서버 ↔ 서버(MSA 내부) 통신에 사용합니다.

왜 브라우저에서 직접 실습하지 않나요? 브라우저는 HTTP/2 프레임을 raw로 제어할 수 없어 gRPC를 직접 호출할 수 없습니다(별도 gRPC-Web + 프록시 필요). 그래서 이 페이지는 개념과 Spring 코드 위주로 정리합니다. 실습은 아래 명령으로 로컬에서 해볼 수 있어요.

세 가지 기둥

요소설명
HTTP/2멀티플렉싱·스트리밍·헤더압축 기본 탑재
Protocol Buffers바이너리 직렬화 → JSON보다 작고 빠름
IDL(.proto)계약을 먼저 정의 → 다국어 코드 자동 생성

① 계약 정의 (.proto)

syntax = "proto3";
option java_package = "com.yanolja.grpc.user";

service UserService {
  rpc GetUser (GetUserRequest) returns (UserResponse);           // Unary
  rpc ListUsers (ListUsersRequest) returns (stream UserResponse); // Server Streaming
}
message GetUserRequest { int64 id = 1; }
message UserResponse { int64 id = 1; string name = 2; string email = 3; }

② 서버 구현 (Spring)

@GrpcService
public class UserServiceImpl extends UserServiceGrpc.UserServiceImplBase {
    @Override
    public void getUser(GetUserRequest req, StreamObserver<UserResponse> obs) {
        obs.onNext(UserResponse.newBuilder().setId(req.getId()).setName("홍길동").build());
        obs.onCompleted();
    }
}

③ 클라이언트 호출

@GrpcClient("user-service")
private UserServiceGrpc.UserServiceBlockingStub stub;

UserResponse res = stub.getUser(GetUserRequest.newBuilder().setId(9001).build());
// 원격 호출이지만 로컬 메서드처럼 사용

4가지 통신 방식

방식설명
Unary일반 요청-응답 (REST 유사)
Server Streaming서버가 결과를 나눠서 계속 push
Client Streaming클라가 여러 번 보내고 마지막에 응답
Bidirectional양방향 동시 스트리밍

로컬에서 빠르게 만져보기

CLI 도구 grpcurl로 gRPC 서버를 직접 호출할 수 있습니다.

brew install grpcurl
grpcurl -plaintext localhost:9090 list
grpcurl -plaintext -d '{"id":9001}' localhost:9090 user.UserService/GetUser
언제? 서버 간 고성능·저지연, polyglot MSA. 외부 공개 API는 보통 REST 병행. 자세한 내용은 강의 문서 07장.
